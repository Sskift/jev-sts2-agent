# 整局实测进展

更新：2026-09-20。目标是同一局标准游戏经过三幕、击败最终 Boss、进入正式胜利结算；当前尚未达到该目标。

当前实现：Node + 游戏内 C# 模组，Jev 选择有策略取舍的完整动作。唯一合法动作和已经选择跳过后的流程推进由代码处理。普通奖励不再结束循环。已加入购买卡牌/遗物/药水、商店删牌、奖励领取/选牌/跳过、遗物和组合选择、水晶球候选及战斗外可用药水。

上下文采用完整 JSON 请求，不依赖 Jev 跨调用记忆。保留当前战斗历史、出牌时的规则和相关资源变化；已结束战斗的战术动作留在本地，跨房间携带构筑与资源变化。重复说明和卡牌状态可在单个请求内去重。上游公布单个问题的状态与问题合计上限为 32k tokens；本地字节限制仅为初筛，实际 token 使用记录在 API 响应中。

第一局 `run-1789840836`（Ironclad、标准模式、进阶 0）在第一幕第 9 层正式失败。第二局 `run-1789842971` 在第 12 层失败，经过精英、休息、商店和附魔。第三局 `run-1789844801` 在第一幕第 17 层 Boss 战失败，敌人剩余 37 生命。第四局 `run-1789846626` 击败第一幕 Boss 仪式兽，正常进入第二幕，在第 33 层无厌沙虫战因沙坑倒计时失败，正式分数 795。第五局 `run-1789848921` 在第一幕第 8 层精英战失败；第六局 `run-1789849429` 在第一幕第 17 层同族 Boss 战失败。日志按时间保存在 `run-artifacts/`；第四、五局最终记忆分别另存于各自最后一次运行目录中的 `final-memory.json`。

实测修复包括：空数组被上游省略、药水使用历史说明空引用、抽牌历史说明误写为弃牌、奖励命令名与注释不一致、重复跳过卡牌奖励、结算胜利字段读取错误、部分选择/商店说明未展开数字。针对目标的伤害使用游戏的预览计算，原始规则文字中的基础伤害与实际预览值明确区分。

网格选牌曾未返回卡牌列表，三次使用截图核对列表后由 Jev 选牌，再用 Computer Use 执行对应点击；没有由助手代替 Jev 选择。模组增加实际卡牌网格后备读取，第二局附魔界面已正常返回卡牌。附魔预览另有隐藏确认按钮误点问题，本次用 Computer Use 完成 Jev 已选卡牌的确认；修复版只点击可见且启用的确认按钮，并返回附魔规则。游戏仅在战斗或事件已结束后正常关闭、部署更新，再正常继续同一存档，没有重置战斗或编辑存档。

第二局的明确决策错误是低血量时忽略了致死攻击。现给候选添加单步生存估算：当前意图的总伤害、执行后的能量和格挡、若立刻结束回合的剩余生命，以及“滑溜”等已知伤害上限。它不是完整战斗模拟，不预测抽牌、触发效果或后续行动，也不代替 Jev 选择。对失败前局面进行无游戏操作的 Jev 回放，模型改选了能保命的“耸肩无视”（75%），后续仍需整局验证。

第三局还暴露出两个策略问题：对有次数限制的伤害上限浪费大攻击，以及临近 Boss、没有后续商店时囤积金币。现补充便宜攻击消耗上限后的已知手牌伤害计算，并明确商店卡牌能量、花费、剩余金币和后续商店距离。对当时商店做无游戏操作回放，Jev 改选购买打折的“狂怒”（59%）。这些是局面回放结果，不能当作胜率结论。

长战斗的上下文整理保留当前事件顺序和所有卡牌规则，去掉地图已有的成功行走记录、成功命令的回显、重复的格挡/能量观察及过时的地图分支。历史表格共享固定字段；当前请求仍自给自足。第四局 Boss 战曾因 60,187 字节超限停在决策前，整理后降至 56,845 字节，继续同一战斗并获胜。

第二幕多敌人战斗再次触发上下文门槛，已去掉每个候选中重复的手牌规则和敌人说明，通过索引关联同一 JSON 的完整状态。更早各幕的资源与构筑变化按楼层范围汇总，完整中间记录保留本地。一次无游戏操作的容量测量中，66,970 字节完整请求成功，实际输入 32,114 tokens，因此将本地字节门槛从 60 KB 调整为 70 KB；这不是服务端 token 限制，服务端拒绝会在动作前停止。

第四局失败时玩家还有 45 血和可用的“仓皇逃离”，但 Jev 将最后能量用于攻击。沙坑即死说明已经在 JSON 中，普通攻击估算却显示仍能存活。现将这项可见倒计时及“仓皇逃离”加一的效果纳入确定性估算，直接致死优先于普通格挡/生命计算。只使用失败前已知局面的无游戏操作回放，Jev 改选“仓皇逃离”（97%）；仍需后续实测，不能等同于战斗胜利。

第五局在只有一张非基础攻击牌时选择了很快遇到精英的路径。现在 JSON 明确统计卡牌类型、基础牌数、非基础攻击与升级攻击数量，选路候选直接附带已有的精英/休息/商店距离和路线数量范围，避免把关键信息只放在较深的地图结构里。分岔局面回放改选推迟精英的分支（83%）。所有合法路线仍提供给 Jev，代码不代替它选择。

当前工程检查：84 项 Node 测试通过；兼容模组使用本机 SDK 8 Roslyn 与游戏程序集编译成功。当前构建标签 `0.111.0-context.5`。实测已确认附魔规则、附魔确认、伤害预览、易伤数值展开和第一幕至第二幕过渡。第二幕地图处正常退出部署规则文字的连续能量图标计数修复，安装 DLL 与构建哈希一致。命名管道连接失败时区分“尚未发送”和“结果未知”，前者重新观察后决策，后者保留待核对状态；Windows 短暂文件共享冲突会重试原子记忆写入。后续流程仍需整局验证，不能据此声称已经通关。

后续：持续修复实际流程阻塞和上下文缺项，继续这局；正常失败后可开始新局。正式通关后在 master 提交最终实现，并更新现有飞书文档，不另建文档。

第六局暴露了重振精神的计算错误：卡牌数值是每张被消耗牌的格挡，不能当作固定收益。现按其他非攻击手牌数量计算，并列出被消耗的牌，零目标时显示零收益。失败前 9 生命、24 来袭伤害的局面回放改选重振精神（92%），可按当时规则保留 1 生命；这只是局面验证。提示补充多敌人集中火力与保留尚未使用的能力牌的取舍。完整第六局记忆已归档。

第七局在营火以 80/85 生命选择了回复，而实际最多只能回复 5。现将当前生命缺口直接写到休息候选旁，并明确锻造的永久收益。无游戏操作的同局面回放改选锻造（61%）。计算型攻击牌原先只有规则文本、没有数值伤害预览；新构建同时读取游戏的 Damage 和 CalculatedDamage 并调用正常目标预览，已编译为 0.111.0-context.3，并在通过第一幕后战斗外部署。


第七局 run-1789850665 击败第一幕同族 Boss，战后 33/85 生命。长战斗在 65,104 字节时被服务端拒绝（max_tokens_exceeded），并未发送游戏动作；按记录形状共享实际相同字段后，无损整理为 60,336 字节，实际 31,165 输入 tokens，继续原战斗并以三张攻击牌获胜。API 错误现记录有限错误类别，便于区分容量问题。

第七局随后在第二幕第 23 层 THE_OBSCURA_NORMAL 战正式失败，分数 392，最终记忆已归档。此前第 22 层假商人被旧模组误判为已完成普通事件，choose_event 被明确拒绝。context.4 统一解析当前可访问的普通/事件库存，使用原生价格、规则和购买方法；完成事件改用 proceed。在战斗外正常重启后，同一局回到相同事件、32/85 生命和 151 金币，成功读取 6 件商品及退出选项。Jev 选择离开，因此这次真实验证覆盖读取与退出，未覆盖事件购买；购买保护通过 24 项隔离模组断言，Node 83 项测试通过。

第七局的战斗决策持续攻击具有 Illusion 的复活随从，主敌人在首回合后一直保留 108 生命。候选现直接指出复活只带来暂时缓解，并明确最后非随从敌人死亡后的随从离场规则；提示区分普通可永久击杀随从与无限复活目标。不操作游戏的同局面回放改选防御（30%），攻击选项主要转向主敌人，不能据此声称已经解决整场战斗。

第八局 run-1789853037 在第一幕第 14 层战斗后以 76/80 生命正常部署 context.5。群攻原先因无需单独选中目标而没有伤害预览，现按游戏 HittableEnemies 集合生成每个实际受击者的普通预览；Node 的首击估算同时计算这些目标，保留有格挡、伤害上限或缺失预览的存活威胁，不推断随机目标。84 项 Node 测试通过，模组编译无错误或警告。多段次数仍只依规则文本理解，不冒用支付阶段的 X 值作为手牌预览。
