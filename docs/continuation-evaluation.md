# 观察后续接与伤害账目回归

2026-09-21。本轮继续修正回合规划和上下文，没有发送游戏命令。**当前使用 OpenRouter，Vercel 与回退均已停用。** 基线是 `198ce72`，全部样本已经用于此前开发，不能称为新的独立测试集。

## 功能变化

- 观察段显式给出剩余能量、尚未消耗的手牌、当前抽牌池及按当前费用可覆盖的数量。成对比较还列出另一方案要用、本方案尚未消耗的手牌，检查当前费用是否容得下。它们只描述继续决策的资源，不假定抽到某张牌，也不保证新效果之后仍能打出。
- 独立 Score 替代前期单向淘汰；不同卡牌／目标分配、不同结束边界和保留资源的观察方案进入最终比较。每组保留评分最高的具体顺序。局部目标不强制影响独立方案评分；最终及结束前复核都交换展示顺序，并对齐概率后汇总，保留分歧。
- 区分伤害计算阶段。旧步骤里的 `per_hit` / `total_before_block` 容易与已经计算 Slippery 等上限后的扣血数字混淆。现在名称明确表示格挡和 HP 损失上限之前的输入，另列逐步扣血、扣格挡、实际使用的限制；已知层数按出牌顺序消耗，未计算修正仍标未知。
- 提供方适配保留 typed Choice/Score、完整响应与置信度。Vercel 的 TypeSafe 置信度来自元数据，未返回的具体上游版本不猜测。可选故障回退与限流冷却不根据答案好坏触发，也不重放游戏动作；当前配置不使用它们。

没有新增运行时依赖，主路径仍为 Node.js + C#。204 项功能检查通过；新增检查针对资源边界、伤害上限、展示顺序和传输路由。

五次合计 124 请求、2,786,619 输入 tokens、10,779 输出 tokens。入围比较中，52 对方案有 20 对在交换展示顺序后改变原始偏好；概率汇总保留这些差异，并没有消除模型的不稳定性。Obscura 请求数从每次 40 降至 27，输入约少 31%；Vantom 和 Hunter Killer 的上下文与比较成本增加，不能称为全面降本。

Vantom 两次都保留能量后抽牌，比旧版初始计划不抽牌、或中间版全部花光后才抽牌，更明确地保留了继续安排的机会。这不是最优性或胜率证明。Obscura 首领即时伤害比上一版少，属于必须继续观察的取舍，不能只挑有利变化报告。
