# Jev 决策管线

2026-09-20：重点由补齐操作转为改善决策质量和顺序。最终仍以同一局正常三幕通关检验，目前未完成。

## 信息组织

1. 游戏内 C# 模组读取当前状态、原生效果、目标预览和合法选项。Node 校验完整性，不覆盖实时数值。
2. 本地保存 [Spire Codex](https://spire-codex.com/developers) Beta v0.111.0 的英文 JSON：595 张牌、298 件遗物、64 种药水、265 种能力、66 个事件，以及怪物、遭遇、关键词、附魔、负面附着等，共 14 类。按 ID 查询并补全关联规则，不需要常驻服务或每步网络查询。
3. `rule_reference` 从当前永久卡组、各牌堆、玩家/敌人状态、商店与候选选择取条目，沿生成牌、能力、关键词等关系展开。`related_rules` 将条目直接关联到对应解释，例如 Speed Potion → Dexterity → 游戏原生的“提升卡牌获得的格挡”。不会展开所有随机牌池。
4. `decision_brief` 放置当前生命、能量、格挡，以及同一战斗最近四个已确认动作、打出时的牌面规则和实际资源变化。新的动作记录保存命令前后的有限快照；早期日志没有这些快照时明确为未知。完整游戏历史继续保留，摘要不冒充模型的长期记忆。
5. 每个 Choice 选项直接附带有限算术：剩余能量、格挡、目标伤害、立刻结束时的生命，以及在既定费用下可支付的后续攻击。条件估算与已观察事实分开，不把未知触发和未来抽牌当作确定结果。
6. Jev 在完整自包含 JSON 上选择一个合法动作。拿牌/购买等选择仍先使用既有独立增益评分；战斗目前保持一次 Choice。代码重读状态、丢弃过期选择、执行一个动作、确认结果，再进入下一次决策。

策略仍由 Jev 负责。没有硬编码固定打法、按评分强制买牌，或把 Wiki 中的后续事件页面变成当前可执行按钮。

## 事实与边界

- 原生实时描述、升级、费用、力量/虚弱后的目标预览、遗物计数器、意图和合法动作优先。静态库明确区分基础与升级规则。
- Wiki 是社区抽取资料。原始全量响应保存在本地，但 `cards_draw` 等解析摘要不参与计算：例如 Blade Dance 的该字段为 3，而原文实际是生成 3 张 Shiv。动态能力模板缺失的金额不能猜成零。
- 事件资料为公开的可能页面；没有数据的页面明确标记缺失。怪物公开招式表与一般规律不表示本局未来随机动作。
- 当前攻击次数只对原生已核实的 Conflagration、Twin Strike、Whirlwind 输出。其他未知次数保持原有保守范围；不模拟攻击前、命中间及死亡触发。Rage 在整张攻击之后触发一次，零次命中的攻击也可以触发；战斗结束等中断仍可能改变结果。
- 历史中出现临时敏捷使用太晚时，请求本来已有 Dexterity 的原生解释。因此规则库只能改善信息组织，不能单独证明解决了决策错误。

## 初步验证

119 项 Node 测试、24 项实际 C# builder/DTO 源码定向断言和完整模组构建通过。context.13 在主菜单安装；尚需新实战验证全部效果。

下面比较两种最终输入：A 已有完整历史、规则库和修正算术；B 另外加入近期动作摘要和候选旁的算术。各局面保留完整原始请求，补入已核实的历史缺失字段，不使用该决策之后的结果。每个最终变体一次真实 Jev 调用，未向游戏发送动作。

| 历史局面 | 两种输入的首选动作 | A 的该动作概率 | B 的该动作概率 |
|---|---|---:|---:|
| Obscura：多段攻击被低估 | Strike 攻击正在进攻的 Parafright | 32% | 42% |
| 无可用防御的零能量回合 | 结束回合，保留 Speed Potion | 67% | 75% |
| Brand 消耗选择 | 消耗普通 Strike，保留强攻击 | 33% | 34% |
| Stomp 的折扣顺序 | 先打普通 Strike | 53% | 39% |
| 敌人 Buff 回合铺场 | 先打 Juggernaut | 54% | 42% |
| Rage 的后续攻击格挡 | 先打 Rage | 47% | 51% |

这六个局面的首选均保持合理，但概率并非全面改善；多个等价或合理动作也会分散概率。它们是用于开发的已知失败样本，不是独立测试集，不代表统计显著的质量或整局胜率提升。[原始结果摘要](evidence/2026-09-20/decision-pipeline-evaluation.json) 保留模型分布、请求体积和实际用量。

新增摘要曾因重复的整手牌/敌人快照触及请求门槛，现只突出变化字段、手牌数量与打出时的牌面。最终这些请求使用约 17k–32k 输入 tokens，最长 31,925。长战斗仍可能触及模型窗口；超过门槛时停止在游戏动作之前，不截断当前卡组和合法动作。

## 下一步

在新实战中检查信息是否真正帮助连贯出牌，尤其是药水→防御、能力→攻击、击杀目标和选牌用途。失败时分别检查事实、计算、组织和模型判断，先用原始局面验证改动，再继续游戏。不要把更多提示或单个回放成功当作通关率已经提高。
