# Jev 决策管线

更新：2026-09-21。当前正常路径为 C# 原生观察 → Node.js 编译上下文 → Jev 选择有序方案 → 模组逐条执行并核对 → 必要时重新规划。最新离线结果见[观察后续接与伤害账目回归](continuation-evaluation.md)。三幕正式通关仍是 active goal，尚未完成；按更新后的目标，完成可落实的优化后恢复新局实战。

## 信息如何进入请求

| 层 | 内容与边界 |
|---|---|
| 当前观察 | 模组 context.17 的生命、能量、各牌堆、费用、目标预览、升级展示、遗物计数、可见意图、方位与合法动作；实时数值优先。 |
| 版本化规则 | Spire Codex v0.111.0 的 14 类本地资料，按当前实体和关联规则取用；原始基础值不能覆盖当前预览。 |
| 策略知识 | 五个角色的适用组合、前提、代价与来源，以及怪物静态行动图；建议与规则分层，不指定固定流派。 |
| 相关历史与意图 | 当前回合、上一轮敌方响应、仍有效的计数／延迟效果／牌序，以及回合目标和未执行计划；每次请求自包含。 |
| 条件分析 | 有序资源、已计算的效果、临时状态、回合末结算、战斗进展及观察断点；未计算的结果为未知。 |

`context_compiler` 统一观察身份和来源分区，保留实体／规则索引，以可逆字典和表格减少重复事实。正在评分或比较的方案优先保留普通具名记录和完整文本，按实际编译体积拆分批次；单个完整判断仍超限时，才回退到完整压缩表示。两种表示均核对完整还原。必要上下文超限时停在游戏动作之前，不截断手牌、卡组或合法动作。90 KB 本地门槛不等于服务端 token 保证，实际用量单独记录。

怪物图区分固定边、相对随机权重、连续重复限制、冷却和未求值条件。`analysis.enemy_outlook` 只用可见意图类型与已知命中次数匹配，保留歧义，最多展开随后两个正常招式。阶段转换、死亡与眩晕等可以中断循环；没有读取内部下一招或 RNG。[本地知识说明](../data/strategy/README.md)记录来源和当前缺口。

## 如何形成一个回合的计划

1. Jev 在共享实际局面中选择本回合目标、主要收益、准备动作及选牌／保留意图，得到一份初始有序方案。目标是可修订的意图，服从整局价值。
2. `independentTurnCandidates` 从各合法卡牌／药水起手独立展开，而不局限于初始提案。默认检查至多 4,096 个前缀，从起手与长度分层取最多 64 个候选；若第一步的合法变体更多，保留各起手。未知抽牌、变形、安装新能力、回收和未计算的下一张牌触发结束当前段。
3. 将这些方案与原提案、删除动作、相邻换序、替换和补入动作等局部候选合并。按实体检查卡牌不重复、药水不重复、准备依赖和能量预留。代码限制搜索范围，不按某种伤害分数或流派偏好排序筛选。
4. Jev 对完整候选独立评分，清空未执行提案的局部目标偏好。前三个不同卡牌／目标分配的代表入围，补入不同结束边界、最高剩余能量的观察候选及原提案，最多六个。每个代表仍是具体的有序方案，不把排列当成相同效果。
5. 方案两两交换 A/B 位置，按对齐后的概率汇总偏好。普通价值也可以回答 `no_clear_difference`；对齐后该结果占优时，双方支持均为 0.5，不将剩余小概率重新归一化成明确偏好。明确的合并生存约束优势优先于普通价值。并列保留原提案，再以稳定标识打破其余并列。保存候选覆盖、评分、入围原因、比较审计和原始置信度；有界筛选仍可能错过好方案。

目标类型、合法命令、候选空间、比较组织和执行约束由代码定义；Jev 负责这些边界内的取舍。当前没有完整跨回合求解器。观察段作为完整替代方案参与比较，但不能将断点后的抽牌或收益当成已发生。

## 有序计算与执行

`turn_sequence` 统一费用、升级、已知属性变化、Tender、Stomp、可确认的 X 费和观察断点。前置动作只影响后续步骤，升级对象按同一实体绑定。无法确定的触发保持未知，不能沿用已失效的原始预览。药水与卡牌的“下一张牌”触发均受相同约束。

`turn_projection` 与 `effect_lifecycle` 区分当前格挡、已知回合末格挡、回合末伤害、反击、有效期和持久资源消耗。普通格挡下次己方回合开始移除；Rage 按攻击牌而非命中次数触发。数字仅覆盖已计算机制，不是完整引擎模拟。

有序步骤将格挡与 HP 损失上限之前的伤害预览，与之后的逐步扣血、扣格挡和已应用限制明确分开。例如有 Slippery 时，6 点牌面预览可以只造成 1 点 HP 损失；消耗最后一层后，下一次攻击才能按相应规则重新计入伤害。未知修正与死亡触发仍使相关账目保持未知。

`encounter_progress` 分开描述 HP 削减、血量归零和永久移除。Illusion 的归零会打断当前攻击、随后复活；未击倒的小额伤害不会取消攻击。其他尚未计算的死亡／复活触发可能使移除、后续伤害或生存估算未知，不能仅凭归零给出确定安全结论。

`turn_plan` 以 run/combat/turn 为作用域，保存目标、revision、有序步骤、cursor、已确认动作、资源预留、准备受益对象和待复核原因。代码逐条匹配当前合法候选，发指令前重读，确认结果后推进。同回合普通连续出牌沿用计划，不为每张牌重新作独立选择。

抽牌、费用／能力／意图变化、死亡、选牌结果或其他外部变化需要重新观察。Jev 获得实际新状态、原目标、已确认动作和剩余计划，可保留或修改方案。命令结果不明确时不推进 cursor，也不自动重发；跨回合、战斗或新局不继承过期计划。

观察段包含剩余手牌、能量、当前抽牌池及费用覆盖信息；成对比较对称列出另一方案所用但本方案尚未消耗的手牌。费用覆盖不是后续合法性或抽牌结果保证。真正结束回合前还有一次实际状态复核；追加提案同样经过双向完整方案比较，再执行短续接段并观察。最终两次 Vantom 回归都在保留能量时选择抽牌，但具体时机仍不同，不能称为已找到最优策略。

抽牌等观察节点的完整回合末结果仍未知，但不会抹掉已知前缀与当前攻击之间的覆盖缺口。`checkpoint_attack_balance` 单独给出已知生命、格挡、当前攻击、攻击覆盖余额、所需额外缓解与剩余能量，明确排除未结算效果和后续动作。第 33 局末回合的完整回放因此改为先抽牌、保留 2 能量；[复盘](run33-review.md)明确没有反事实存活或胜率结论。

## 非战斗决策与验证

地图提供真实节点／边、未知房间标记及各分支的一条最少已知精英路线示例，供恢复、精英与奖励取舍，不将示例称为最优路线。选牌、升级、消耗、弃牌、回收、放牌堆顶、商店和营地各有语义；意图跟随实际对象和资源跨界面传递。Wiki 的潜在事件页面不会变成本局当前按钮。

主循环与离线回放保留实际请求、完整响应和使用量。置信度只是模型返回的选择分布信息，不是正确率或通关概率。已接触样本只报告回归，失败、中间版本和成本一并保留；不会把方案变化直接解释为胜率改善。

第 33 局的换牌药水曾在使用后选择零张。规则与已消耗记录原本已在请求里；明确添加“弃零抽零”并未改善回放，因此该说明试验未合入代码。当时手里已有三张1费攻击，不能直接断言零换牌是错误，问题应从使用药水之前比较。增加无明确优劣选项后的完整回放改选三张攻击、保留药水；第 32 局的节段收尾回归仍选择三张攻击。66 次官方 Jev 调用、30 项相关检查通过；两例仍分别有 5/6、3/6 对位置分歧。[证据](evidence/2026-09-21/run33-comparison-review.json)保留未采用试验和原始比较。这与官方所述[数值、间接推理及结构一致性限制](https://docs.typesafe.ai/model-jaggedness/jev-1.13)相关，但两个开发案例不能证明普遍改善。

第 33 局 Boss 首回合的同事实、同问题诊断显示，普通具名方案比深层压缩表示更容易被模型理解。完整规划回放从单张 Stomp 改为 Peck → Stomp，同样 3 能量的已知总伤害由 51 增至 63，仍漏掉可达到 75 的另一张攻击。37 项相关检查通过；26 份历史大判断的容量核查中，20 份需要完整压缩回退，均能装下。这是开发样本上的有限改善，不是最优性或胜率结论；[证据](evidence/2026-09-21/run33-readable-plans.json)保留未采用的说明差值试验和仍存在的位置分歧。
