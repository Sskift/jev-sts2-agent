# 效果时序 harness：历史对照评估

2026-09-20。本轮没有启动新对局，也没有向游戏发送命令。实现修正了效果时序和部分错误算术；开发样本出现局部改善，但留出评估**没有证明决策质量稳定提升**，并保留了药水顺序退步与无效后续动作等反例。

## 改了什么

- 当前模型 JSON 的 `analysis.combat_effects` 统一列出来源、作用对象、当前层数、已生效／待打出／待使用、触发点、失效点及覆盖范围。它由实时状态和版本化规则组织，不是新的策略选择器，也不增加一层模型调用。
- 区分 Thorns 的逐次命中前反应、Flame Barrier 的命中后反应及敌方回合末失效、One-Two Punch 的玩家回合末失效。当前牌面与层数始终优先，Wiki 示例数字不当作实时数值。
- 方案分析列出临时效果的后续使用者，以及结束时尚未使用的次数；保留抽牌、生成牌和自动出牌的不确定性，不一律禁止“没有使用者”的动作。
- 将留在手中的 Burn / Toxic 和可确认来源的 Constrict 计入回合末伤害，与早期格挡的时序对应。Constrict 只有唯一可见 Slithering Strangler 来源时才计算；来源不明或其他未计算的回合末生命效果，使最终生命等相关数值保持未知。
- 原始规则仍完整保留。未知机制不会因为缺少适配器就变成零效果；目前仍不是完整模拟器，通用的动态数值和变形依赖传播尚不完善。
- 主循环新增完整 Jev 原始响应记录，保留提供方返回的概率分布和置信度。置信度不解释为赢面或已校准的正确率。

事实来源是[Spire Codex 开发接口](https://spire-codex.com/developers)、[本地 v0.111.0 快照](../data/spire-codex/README.md)和本机对应版本的原生机制核对。公开接口复核了 [Constrict](https://spire-codex.com/api/powers/CONSTRICT?channel=beta)、[Thorns](https://spire-codex.com/api/powers/THORNS?channel=beta)、[One-Two Punch](https://spire-codex.com/api/cards/ONE_TWO_PUNCH?channel=beta)、[Flame Barrier](https://spire-codex.com/api/cards/FLAME_BARRIER?channel=beta)。精确触发先后不能只靠 Wiki 的“本回合”措辞推断。游戏二进制与反编译源码未提交。

## 方法与限制

开发资料使用第 23—27 局；第 20、21、22 局作为本轮留出集。[划分约定](../eval/harness-split.json)先于留出模型结果固定。早期开发已经分析过这些历史局的部分问题，因此它们不是完全未见过的独立基准。

基线为 `b4ac38f8c4441ed825bfa6a35d782f84827ff776`。开发集反伤样本曾使新旧版本共同报错：压缩后的 `affected_outputs` 可以变成 `text_ref`，旧 Schema 却只接受字符串。正式比较为双方施加同样的格式兼容修正，不改基线事实、提示词、候选或选择策略；原来的两份失败记录保留。

候选代码在选择留出快照前冻结，文件哈希清单存于本机 `run-artifacts/harness-evaluation/freeze.json`，摘要为 `36c6c3adc721660cb993b963bacd4e73d6b20f4de7d3b5b723947f8a8d020686`。评估后没有根据留出结果修改实现。

原定规则：每局最后一场战斗，第 1、3 回合第一个可操作快照，共 6 个局面。每个局面旧、新 harness 各运行两次。重建记忆只读取该快照之前已确认的观察、动作和战略记录；双方使用相同的状态、记忆及输入哈希，关闭新增整局战略评估。没有输入未来抽牌、动作或结局。实际返回模型均为 `typesafe/jev-1.13-20260917`；没有控制模型采样，两次重复只能暴露部分波动。

第 21 局 Boss 使用旧模组记录，缺少 Surrounded 所需的玩家朝向。原定两个局面共 8 次尝试均在调用模型前停止，没有猜造朝向。为补充覆盖该局，在保留原失败的同时，另按“该局最近一场第 1、3 回合字段完整的战斗”选择第 29 层 Hunter Killer。此规则在补充模型调用前确定，代码继续保持冻结；它是兼容性失败后的补充评估，不替换原定测试集。

下面列出的都是**首个命令前生成的计划**。升级、抽牌、变形等在真实执行时会触发再观察／复核；离线回放没有执行这些检查点后的游戏状态，不能将整段计划当作真实轨迹，更不能推算整局胜率。

原定 24 次尝试中，16 次返回完整决策，8 次因朝向字段缺失而停止；补充 8 次全部返回。总计 24 份可比较的新旧规划，来自 3 局、6 个可用局面；另保留 2 个不可用局面。全量摘要、逐次置信度及输入哈希见[证据 JSON](evidence/2026-09-20/harness-evaluation.json)，原始请求／响应位于其中给出的本机目录。

成功的留出及补充规划合计：旧版 339 次模型请求、6,260,426 输入 tokens；新版 362 次请求、6,968,200 输入 tokens，分别增加约 6.8% 和 11.3%。新增效果表自身没有额外模型阶段，但上下文增大、模型选择不同会改变规划分支与调用量，当前没有性能优化结论。

## 工程收敛与后续边界

保留 Node.js + C# 模组主路径及可选录像／窗口工具；删除未使用的视觉决策循环、视觉模型客户端、烟雾脚本、通用演示入口及对应旧测试。无新增运行时依赖。[README](../README.md)已按当前主路径重写，[计划](plan.md)移到仓库内，不再指向飞书方案。

本轮检查为 177 项通过，以及真实历史输入的模型回放；未用合成测试通过代替决策质量结论。

当前可确认的是事实表达和条件分析修复，不能把留出中的错误全归咎于模型：候选仍有零能量后续攻击、变形后的陈旧牌引用，以及动态数值依赖覆盖不足。下一轮应处理这些通用依赖与候选比较问题，并重新划定评估样本；本轮不根据测试集继续调参，也不恢复实战。
